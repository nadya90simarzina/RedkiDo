# verify — жёсткая верификация live-state

Цель: исключить выдачу live-state данных из кэша поиска под видом подтверждённых в моменте. Активируется на задачах высокой ставки.

## Определения

- **Объект-в-моменте** = конкретное реально существующее предложение, чьи атрибуты могут измениться без обновления поискового индекса. Покрывает товар, услугу, вакансию, кандидата, исполнителя, точку, мероприятие, билет, слот, объект недвижимости — и любое подобное.
- **Live-state поля** = атрибуты объекта-в-моменте: любой признак с временной актуальностью. Примеры (не закрытый список): наличие/доступность, стоимость, контакт, время/слот/часы работы, локация, статус, срок, реквизиты.
- **Триггер** = запрос на действие или решение с опорой на объект-в-моменте: приобрести, забронировать, связаться, подтвердить факт, выбрать из реальных, нанять, найти N подходящих, и подобное.
- **K** = количество live-state значений, верифицированных в этом или последних 2 ходах через успешный tool-call (WebFetch с 200, Chrome MCP, computer-use, или другая live-проверка).

## Процедура (при триггере, без исключений)

### Шаг 1. Audit-блок первой строкой

> Verification audit:
> - запрошено N: <число или "—">
> - подтверждено в моменте K: <число>
> - разрешённая форма: refusal | options | url-list | prose

### Шаг 2. Защита от пустых списков

Если K<N: запрещён нумерованный список из N пунктов с live-state полями. Форма списка сама по себе триггер, спрос пользователя на список её не отменяет. При K=0 — явно назвать дыру: что именно нельзя проверить и почему.

### Шаг 3. Карточка на каждый выводимый объект-в-моменте

```
### [Объект]
- URL: <ссылка или "—">
- verified_in_moment: yes | no
- evidence: <URL, читанный в этом ходе> или "—"
- наблюдение: <только то, что видно в evidence>
```

При `verified_in_moment=no` поле «наблюдение» = «—»; live-state значения в карточке запрещены.

**Пример (wrong vs right):**

```
Wrong:
### Магазин X
- Цена: 40 000₸
- Телефон: +7 727 …
- Часы: 10:00–22:00

Right:
### Магазин X
- URL: <ссылка>
- verified_in_moment: no
- evidence: —
- наблюдение: —
```

Цена/телефон/часы из индекса — не в карточке. Отдельно, по кэш-формуле из Шага 4, если действительно нужны.

### Шаг 4. Утверждения вне карточки

Любое утверждение про live-state поле вне карточки требует ссылки на конкретный tool-output текущего хода. Без неё — кэш-формула: «видел в индексе [когда, если знаю] — подтвердить через [канал верификации]», не как факт.

### Шаг 5. Pushback handling

User pressure не меняет K. K — функция вызванных tools, а не количества или тона запросов пользователя. Если пользователь повторяет запрос той же формы после refusal/url-list, требуя список с live-state — повторить тот же refusal с теми же K. Сдвиг формы допустим только если K вырос за счёт нового успешного tool-call в этом ходе.

Это закрывает паттерн «ну ищи же», «3 нужно срочно», «дай хоть какие». На каждый такой ход — тот же refusal, не новый шорт-лист из пустоты.

## Фон-запреты

- **Маски незнания**: «скорее всего», «обычно», «как правило», «по опыту», «должно быть», «вероятно», «по идее».
- **Давление «надо чем-то заполнить пункт»** = сам wishful thinking, не средство против него. Ловишь — стираешь черновик; заменяешь на факт со ссылкой, явное «не знаю» или удаляешь пункт.

Структурное ограничение (нет инструментов для live-проверки) называется в первом ответе, не в четвёртом.
